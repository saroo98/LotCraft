## Required behavior

- A saved SL belongs to the exact symbol on this chart, within the current account/server namespace. No absolute forex price may migrate to gold or an index.
- Returning to a saved symbol restores its Entry/SL/TP/direction/mode. Instant Entry can follow the live quote; SL stays at the saved price.
- A stored finite plan is not discarded merely because a changed quote or broker constraint makes it non-executable. Risk/order validation reports that condition.
- Fresh symbols get a broker-scaled initial plan. Saved plans are not enlarged or moved for visual appearance.
- Planning remains usable while closed or restricted. Execution can still be blocked for real market closure, missing data, permissions, invalid stops or capacity.
- No fabricated guarantee about the friend's terminal: exact broker/version/error evidence is unavailable.

## External dependencies and deliberate non-changes

1. Hyper-V `Get-VM -ErrorAction Stop` is permission-blocked in this context. No configured isolated MT5 environment was established. Native UI, restart persistence, Win32 and broker acceptance remain unproven. No desktop access was attempted.
2. Obtain the friend's exact LotCraft error or MT5 retcode, symbol suffix, order mode and release version before attributing his remaining trade block. A real closure, stale quote, account permission, invalid SL, unsupported order type or broker rejection must remain a block. Do not disable those guards to make the button clickable.
3. Persistence uses the existing terminal-global account/server/chart namespace. MT5 removes a global variable after four weeks without access, and a new chart/account/server has a different namespace. Normal symbol and timeframe cycling now retains each plan, but indefinite archival across inactivity is not promised. See [terminal-global lifetime](https://www.mql5.com/en/docs/globals). A durable backup would be a separate storage change. Multi-key storage is not crash-atomic.
4. The published and installed 1.2.0 copies are not updated by this audit. Production read-only hashes are captured for the final immutability comparison. No release signing key is read. No old updater folders or unrelated files are deleted.
