# LotCraft 1.2.1 known limitations

Current release status and evidence are in [the 1.2.1 report](RELEASE_1.2.1.md). The [September 30 audit](AUDIT_2026-09-30.md) and [earlier verification report](AUDIT_VERIFICATION_2026-09-09.md) record pre-release snapshots. Screenshots, installations and completion reports do not prove native behavior in MT5.

1. Native runtime acceptance is pending. This audit does not control the desktop, launch MT5, place trades or alter production installations. Hyper-V inventory is permission-blocked. Offline function tests and compilation do not prove actual rendering, UTF-16 handling, mouse capture, DLL integration, restart persistence, multi-chart behavior or broker execution.
2. DLL permission is mandatory. Initialization requires Windows integration for clipboard, native order-dialog access and pointer-release recovery. Strategy Tester does not launch the updater.
3. Instant Entry follows Ask for Long and Bid for Short. Dragging its E handle intentionally changes to Pending. SL/TP stay fixed through mode changes. Saved symbols restore their own plans; unseen symbols receive symbol-scaled prices. A preserved invalid SL disables execution instead of being moved. Native transition/drag acceptance remains pending.
4. Pending expiration supports GTC or DAY. Specified-date-only symbols have no corresponding input and are rejected. New orders are conservatively blocked on nonhedging accounts when the current symbol already has a position.
5. Minimum-volume sizing can exceed Target risk. Actual SL loss reports the final-volume estimate. Broker caps, remaining volume limits, missing data or invalid stops can still prevent trading. Not every requested amount is executable.
6. SL exposure is a projection, not a guaranteed close result. It uses entry, volume and SL, includes accrued swap for positions, and is downside-only. Profitable stops do not offset other losses. Future swap, gaps, slippage and unknown closing fees cannot be predicted and are excluded. Rows without an SL or a valid projection are reported as incomplete and are never counted as zero. Current UI initialization sets commission to zero; no visible commission editor is provided.
7. Exposure percentages use current equity, not the selected Balance or Manual sizing basis. Inventory count checks detect count drift but cannot establish a frozen snapshot if tickets change with the same count. Broker conversion rates and unusual contract rules need isolated acceptance. Extreme malformed finite broker values can overflow aggregate arithmetic; stronger numeric-domain handling is a follow-up hardening candidate.
8. New-order confirmation is one native risk-only MessageBox. It cannot style the actual-risk line independently. A changed eligible SL-batch target set has a separate reconfirmation path.
9. Version 1.2.1 offers a launch after ten seconds and then hourly while attached. Network attempts are throttled for 24 hours, including failures. Old 1.2.0 EAs only launch after initialization. Offline/closed terminals, missing DLL permission, verification failures and deferral prevent a universal notification deadline. Updates never forcibly restart MT5.
10. The installer is not Authenticode-signed. Embedded-key Ed25519 verification protects subsequent updates but does not independently authenticate the first installer download. The local installation manifest is hash-checked, not signed.
11. Upgrades use per-file renames and rollback, not a crash-atomic multi-file transaction. Power loss or an unrecoverable restoration error can require manual recovery. Uninstallation and terminal-global persistence are also not crash-atomic transactions.
12. Base panel dimensions are Full 438x547, Compact 372x492 and Mini 360x92. Scaling bottoms out at 0.82. Approximate minimum panel sizes are 359x449, 305x403 and 295x75, plus a desired 8px chart margin. Smaller charts need a separate overflow design. Long displayed values may be abbreviated; focused numeric text scrolls within its field.
13. Existing public v1.2.0 verification evidence contains absolute workspace paths. New report generation uses artifact names, not private paths; older published assets are not modified by a new release. No account or terminal identifier was found in that checked historical asset. Historical images are not current UI evidence. Existing orphaned updater temporary directories are not swept or deleted by this release.
14. Plans remain scoped to account/server/chart. Terminal globals expire after four weeks without access and are not an indefinite archive; a different chart ID cannot read another chart's namespace. Partial-write/crash recovery is unproven. Handle separation preserves true prices rather than widening a saved SL. If an extremely narrow chart has no safe exposure-label lane, the details list remains available instead of labels covering controls.

These limits are not claims that all other behavior is defect-free. Review the audit's findings, tests and external dependencies before deployment.
